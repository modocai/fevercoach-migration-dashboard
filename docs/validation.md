# 구현 및 검증 기록

## 범위와 근거

- 시작 기준: 대시보드 main의 `fa6697139a3747e7b8c789668650018a6c85c42b`.
- 기존 28개 작업·6단계·디자인 유지. 앱 프레임워크·서버·DB 추가는 불필요하다.
- 공개 URL 추출과 전체 이전이 다르므로 Wix 상태 JSON의 허용 필드만 연결한다.
- 열린 이슈는 보드 상태를 대신하지 못하므로 Project 접근 실패는 미확인으로 표시한다.
- 두 HTML을 각각 수정하는 오류를 막기 위해 데이터·템플릿·생성기를 분리한다.
- 자동 커밋은 만들지 않는다. 변경은 본인 계정으로 검토·커밋·푸시한다.

## 루프 1 — 데이터 범위와 상태 해석

기존 HTML에서 28개 작업을 추출하고 단계별 작업 수 4/7/8/3/4/2를 확인했다. 실제 API 조회에서 이슈와 Wix 자료를 수집했다. PR #29는 작업 수에 포함하지 않았다. Project 조회는 `read:project` 권한 부족으로 실패했으며 이를 데이터에 보존했다.

검증: PR·다른 저장소 제외, 누락·중복 응답 거부, 열린 이슈의 상태 미추정, 취소 이슈 미완료 처리, 페이지네이션, 이전 데이터 보존, 추출 범위 분리, 증빙 없는 단계 통과 차단.

## 루프 2 — 정적 화면 생성

검증된 데이터에서 두 HTML을 동일하게 생성한다. 출처·일시·실패를 표시하며 미측정 값은 0이 아니다. 외부 텍스트는 HTML로 실행되지 않게 이스케이프한다.

검증: 생성 재현성, 두 파일 동일성, 28개 링크, JavaScript 없이 작업 표시, 모든 원본 실패 상태, 오래된 기록·상태 불일치 표시, 외부 스크립트·토큰 부재.

## 루프 3 — 브라우저 및 배포 전 검증

대시보드의 필수 사용 환경은 데스크톱·노트북이다. 1440×900 및 1280×800에서 키보드 필터, 빈 결과, 단계 바로가기의 필터 초기화를 확인한다. JavaScript 비활성 상태에서도 28개 작업이 보이며 외부 요청이 없다. 기존 반응형 CSS는 보존하지만 모바일 UI는 인수 기준에 포함하지 않는다.

## 엄격 재검토

기존 검증을 재실행하고 원격 브랜치·PR·커밋 작성자·측정 원본을 대조했다. Lighthouse 두 측정의 수치와 SHA-256이 로컬 원본 보고서와 정확히 일치한다.

검증 계층에서 성공 표시만 있고 Wix 자료 본문이 없는 스냅샷을 허용하는 빈틈을 재현했다. 성공 상태와 오류 메시지의 동시 존재, 잘못된 갱신 결과의 이전 정상 기록 덮어쓰기도 회귀 테스트로 재현했다. 추가한 세 테스트가 수정 전 실패하는 것을 확인한 뒤, 원본별 결과를 저장 전에 검증하고 전체 스냅샷도 파일 교체 전에 검증하도록 보완했다. 수정 후 29개 검증이 모두 통과했다.

판정: 구현·기록·데스크톱/노트북 화면 검증은 통과. Project 및 Actions의 실제 운영 연결은 권한·설정 확보 후 검증해야 하므로 전체 연동 완료로 판정하지 않는다. Search Console·GA4·스테이징 측정과 팀의 단계 기준 확정도 대기 상태로 유지한다.
